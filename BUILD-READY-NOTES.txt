PieFi OS Lite V3 - Build source and branding notes

1. Extract this archive into ~/piefi-build-v3, preserving the top-level contents.
2. The firmware user-facing identity is PieFi OS Lite V3 (boot banner, terminal, OS release display, LuCI header, and PieFi dashboard/portal). The existing OpenWrt 25.12.6 ImageBuilder remains the technical build base for compatibility.
3. It now locates/copies nginx restrict_locally from the ImageBuilder build_dir.
4. First boot uses the user-requested fixed administrator credentials:
   username admin; password piefi3645. Credentials are also written to
   /root/piefi-initial-credentials.txt (root-only permissions, mode 600).
   The Flask session secret and OpenNDS FAS key remain randomly generated.
5. Build output is written to ~/piefi-build-v3/output/PIEFI-V3-UPDATED.
6. The internal distribution ID remains OpenWrt for package and sysupgrade compatibility; visible branding is PieFi OS Lite. Build success and gzip/hash checks do not prove hardware boot, networking,
   captive-portal enforcement, voucher authorization, or payment integration.
   Those require testing on the Dell Wyse 5070 and connected network hardware.

Do not expose the initial credentials file or share its contents publicly.

7. ESP32 primary / ESP8266 backup coin integration is in firmware/ and app/coinpay.py. Admin setup: /admin/coin. Configure packages and exact pulse mappings; no assumed prices are enabled.
8. Payment sessions bind to OpenNDS client IP/MAC/HID and coin event IDs are idempotent. One active customer coin session at a time.
9. Hardware/OpenNDS runtime validation is still required; see COIN-INTEGRATION-README.txt.
10. BinAuth argument indexes are aligned with OpenNDS v10+ documented auth_client/client_auth arguments; voucher and coin sessions are correlated by the OpenNDS client token. The admin disconnect action now invokes ndsctl deauth.
11. The sessions database schema now includes nds_token and migrates existing databases before BinAuth inserts authenticated sessions.
12. Build script discovers the ImageBuilder manifest and combined image by the x86/64 generic profile name rather than assuming a PieFi-prefixed ImageBuilder filename.
